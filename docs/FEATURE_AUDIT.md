## 6. 오류 및 개선 필요 사항

### P0 — 다른 일보다 먼저

#### N-1 🔴 사고를 맡은 가족이 탈퇴하면 서버 전체의 사고 타이머가 멈춤 (`재현`)

- **근거:** `accounts.py:402`가 사용자를 지우면서 `incidents.checked_by`를 정리하지 않습니다. 30분 뒤 `incidents.py:203`의 `_notify` → `alerts.py:116` INSERT가 외래 키 위반으로 실패합니다. `incidents.py:169`의 반복문에 사고별 보호가 없어 `tick`이 매번 중단됩니다. `background.run_each`는 로그만 남겨 겉으로 드러나지 않습니다.
- **재현:** 임시 DB에서 12회 중 12회 `IntegrityError: FOREIGN KEY constraint failed`. 같은 시점의 **다른 그룹 사고도 12회 모두 `detected`에 머물렀습니다.**
- **영향:** 서버 전체에서 60초 → 가족 알림, 180초 자동 처리가 멈춥니다. 다른 가족은 낙상 알림을 받지 못하고, 아무도 이 사실을 모릅니다.
- **해결:** 탈퇴 시 맡은 사고를 되돌리고, 사고별로 예외를 분리합니다. 회귀 시험을 추가합니다.

#### F1 🔴 일어난 뒤 다시 넘어져도 알림이 없음 (`코드`, 기존 시험이 이 동작을 고정)

- **근거:** `LegacyFallLogic.java:77,84`, `fall_logic/legacy.py:74`, `models/fall_detector.py:496`. `tests/test_legacy_engine.py:53`이 "알려진 문제"로 기록.
- **영향:** 사람 ID는 5초 넘게 안 보여야 풀립니다. 일상 오탐 한 번이 ID를 소모하면, 같은 자리에서 일어난 **진짜 낙상이 무음**이 될 수 있습니다. 실제 빈도는 📱 측정 필요.
- **해결:** 옛 규칙에도 FallAlertsV2의 "2초 일어남 → 초기화"를 적용합니다. 기존 시험 기대값이 바뀌므로 사용자 승인이 필요합니다.

#### P0-1 🟡 HTTP 평문 (`코드`)

`run_server.bat`이 `0.0.0.0` HTTP로 시작합니다. 방화벽이 외부 8000번을 막고 있어 실사용 전까지는 치명적이지 않지만, 서비스 공개의 전제 조건입니다. HTTPS는 **보류 항목**입니다.
