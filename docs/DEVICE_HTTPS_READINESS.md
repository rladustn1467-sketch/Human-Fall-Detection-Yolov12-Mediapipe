## 먼저 보는 다섯 가지 답

1. **실제 기기 없이 개발을 많이 진행할 수 있나?** 네. 남은 앱·서버 작업 대부분은 에뮬레이터와 가상 기기로 만들고 시험할 수 있습니다.
2. **기기가 생기면 연결만 하면 되게 준비할 수 있나?** Android 폰은 **설치·코드 입력·측정만 남기는 수준까지** 가능합니다. 다만 절전, 발열, 방향은 실측 뒤 조정이 생길 수 있습니다. 홈캠은 제품을 정하기 전에는 불가능합니다.
3. **HTTPS 때문에 막힌 것은?** 생각보다 적습니다. 외부망에서 서버 접속, 배포용 APK 사용, LAN 주소에서 초대 QR 카메라, 쿠키·토큰 평문 전송 문제입니다. **낙상 감지, 카메라, 푸시 전송은 HTTPS와 무관합니다.**
4. **무료로 해결할 수 있나?** 시험용은 **이미 가능합니다**(Cloudflare 퀵 터널, 이 PC에서 2026-10-26 동작 기록). 고정 주소는 Tailscale Funnel이 현실적인 무료 후보입니다. 단 어느 방법이든 **PC가 꺼지면 서비스가 멈춥니다.**
5. **무엇부터 하나?** 앱이 조용히 멈추지 않게 만드는 작업입니다. TOP 5는 맨 끝에 있습니다.

## 3. HTTPS가 없으면 정확히 어디서부터 막히는가

### 항목별 판정

| 항목 | HTTP 로컬 | HTTPS 필요? | 막히는 이유 |
|---|---|---|---|
| 웹 접속·로그인 | 됨 | 외부 공개 때 필요 | 평문 전송. `_cookie_secure`가 HTTP에서는 Secure를 끔 `[코드]`, 그래서 로그인은 동작 |
| 가입·인증 | 됨 | 외부 공개 때 필요 | 같음 |
| 앱-서버 연결 | **debug만 됨** | **release는 필수** | **Android 보안 정책.** release는 HTTP 차단 `[일반]`, debug NSC는 localhost만 허용 `[코드]` |
| 앱 카메라 감지 | 됨 | **불필요** | 네이티브 CameraX라 웹 보안과 무관 `[코드]` |
| 카메라 영상 처리 | 됨 | **불필요** | 기기 안 처리 |
| 초대 QR 카메라(웹) | localhost만 | LAN 주소면 필요 | **브라우저 정책.** `onboarding.js:323` `isSecureContext` 검사 `[코드]`. 코드 직접 입력으로 대체 가능 |
| 기기 페어링 | 됨 | 외부망·release는 필요 | 앱 접속 문제와 같음 |
| API 요청 | 됨 | 외부 공개 때 필요 | 네트워크·보안 |
| 낙상 전송 | 됨 | 외부망은 필요 | `DeviceLink`는 HTTP/HTTPS 공통, release는 HTTP 차단 |
| 사진 업로드·조회 | 됨 | 외부 공개 때 필요 | 사생활 정보 평문 전송 |
| **FCM 푸시 전송** | **됨** | **불필요** | 서버가 `fcm.googleapis.com`으로 나가는 호출 `[코드]` `push.py:61`. 다만 앱이 토큰을 등록하려면 서버에 닿아야 함 |
| 실시간 통신 | 됨 | 해당 없음 | 폴링 방식. 웹소켓·SSE 없음 `[코드]` |
| 외부망 접속 | 안 됨 | **네트워크 경로가 핵심** | **HTTPS보다 인바운드 경로 문제.** 방화벽 8000 차단 `[시험 10-29]` |
| 홈캠 연동 | 해당 없음 | 설계에 따라 다름 | 집 안 처리면 불필요 |

### 다섯 가지 질문

1. **HTTPS가 없어서 실제로 동작하지 않는 것:** 배포용 APK, 외부망 접속, LAN 주소의 QR 카메라.
2. **HTTPS 없이 개발·시험 가능한 것:** 거의 전부. 에뮬레이터, 사본 서버, FCM, 감지, 사고, 사진, 알림.
3. **이유 구분**

| 원인 | 해당 항목 |
|---|---|
| Android 보안 정책 | release 앱의 HTTP 차단 |
| 브라우저 보안 정책 | QR 카메라, Secure 쿠키 |
| Firebase 정책 | **해당 없음** |
| 외부 네트워크 | LTE·다른 Wi-Fi에서 PC로 접속 불가. HTTPS만으로 해결되지 않고 터널이 필요 |
| 보안 요구 | 비밀번호·건강정보·기기 토큰·사진 보호 |

4. **우회 시험 방법:** 에뮬레이터 + `adb reverse` + `http://localhost` (지금 쓰는 방식), USB 연결 실제 폰도 같은 방식 `[일반]`, 로컬 인증서 `tools/dev_tls.py` `[시험 10-26]`, 퀵 터널 `[시험 10-26]`. `10.0.2.2`는 WebView가 secure context로 보지 않음 `[일반]`.
5. **개발이 완전히 막히는 단계:** **없습니다.** 막히는 것은 "USB 없는 실제 폰을 일반 사용자처럼 쓰는 시험"입니다. 그것도 퀵 터널로 시험은 가능합니다.

### 이번에 찾은 설계 제약

서버 주소가 **APK 안에 고정**되고 `[코드]` `capacitor.config.json`, 감지 기기도 연결할 때의 주소를 저장합니다 `[코드]` `DetectorActivity:89`, `DetectorPlugin:24`. 그래서 **주소가 바뀌면 APK 재빌드와 기기 재연결이 필요합니다.** 퀵 터널을 시험에만 쓰고 고정 주소가 필요한 이유입니다.

`deploy/https/README.md`의 환경 설명은 일부 낡았습니다. 추천안 A(공인 IP + Caddy)는 80·443 인바운드가 필요해서, 방화벽을 바꾸기 어려운 학교 PC 조건과 맞지 않습니다.

## 4. 무료로 HTTPS를 구축하거나 대체할 방법

조건: Windows 학교 PC, 항상 켜 둘 수 없음, 방화벽·네트워크 변경 어려움.

| 방법 | 비용 | 도메인 | 진짜 HTTPS | 현재 서버 유지 | 난이도 | 장기 안정 | 인바운드 | 제한·판정 |
|---|---|---|---|---|---|---|---|---|

### 주의

- **PC가 꺼지면 터널도 서버도 멈춥니다.** 60초 타이머와 푸시 전송도 멈춥니다. 무료·무카드로 상시 가동을 해결하는 방법은 찾지 못했습니다.
- **학교 규정:** 터널은 학교 PC의 서비스를 인터넷에 공개합니다. 방화벽을 건드리지 않아도 규정에 어긋날 수 있어 지도교수나 전산 담당자 허가가 필요합니다.
- **공개 범위:** 공개되면 옛 경로와 공용 토큰도 함께 노출됩니다. 고정 주소로 상시 공개하기 전에 옛 경로를 정리해야 합니다.
- **학교망:** 퀵 터널은 10-26에 동작했습니다. 지금도 되는지와 7844 포트 상태는 `[미확인]`입니다.
