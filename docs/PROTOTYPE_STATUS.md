# 프로토타입 기능 현황과 다음 작업

- **조사 기준일:** 2026-11-04
- **기준:** GitHub main 과 운영 코드 `e5b3fe0` 을 조사하고, 그 뒤 작은 오류를 고침
- **목표:** 상용 출시가 아니라, 집안 낙상사고를 AI 로 감지하는 아이디어를 실제로 구현해 시연하는 프로토타입. 인프라보다 핵심 기능과 사용자 경험이 우선입니다.

## 판정 기준

1. 구현 완료 및 시험 통과
2. 구현 완료했지만 실제 환경 검증 필요
3. 일부만 구현
4. 미구현
5. 오류 또는 개선 필요

코드가 있다는 것만으로 판정하지 않고 실제 호출 경로를 확인했습니다. 실제 휴대폰 시험은 아직 없습니다.

## 시험 결과

서버 350, 루트 104 (건너뜀 4), JVM 72 (건너뜀 1), 브라우저 24, 에뮬레이터 실제 앱 46 통과. 모두 가상 환경입니다.

조사에서 찾은 항목은 이번에 모두 고쳤습니다. 다음 운영 반영 때 함께 올라갑니다.

### 기존 기능 완성

| 항목 | 상태 |
|---|---|
| 사고 대응 안내 | 완료. 가족 긴급 화면 4줄, 대상자 화면 1줄 |
| 재감지 때 긴급 화면 다시 띄우기 (N-14) | 완료 |
| 신고 결과 푸시 (E-1) | 완료 (DB 16) |
| 재전송 때 감지 시각 사용 (D-3) | 완료. 최대 60초만 앞당겨 가족의 대응 시간을 남김 |
| 약관 보기와 동의 시각 저장 (A-6) | 완료 (DB 16). 법률 검토는 받지 않음 |
| 비밀번호 변경 (A-5) | 완료 |
| 낙상 예방 탭 (G-3) | 완료. 집 안 점검과 생활 수칙 |
| '이 휴대폰' 기기를 구성원 본인이 연결 (N-8) | 완료 (사용자 결정 2026-11-04). 구성원이 받은 코드는 공기계에 쓸 수 없음 |
| 집 연결과 대상자 분리 (N-4) | 정책 결정 필요. 규모 큼 |

사고 대응 안내는 공식 원문을 찾지 못해, 지자체 행동요령과 교육자료의 공통 내용만 썼습니다. 무리하게 일으키지 않기, 의식·호흡 확인, 위험하면 119 전화까지이며 치료 지시는 넣지 않았습니다.

### 실제 기기에서 확인할 항목

- 카메라, 초당 처리 장수 (15장 이하면 빠른 낙상 판정이 약해짐)
- 화면 꺼짐, 미충전, 제조사 절전, 장시간 동작. 필요하면 WakeLock 추가
- 폰 방향, 설치 확인 기준값, 어두운 방
- 실제 낙상 흉내와 일상 동작의 오탐. **이 결과로 v2 전환을 결정**
- 운영 서버에서 보낸 푸시 수신
- 뒤에서 재시작할 때의 카메라 제한

Android 폰은 USB 연결과 `adb reverse` 로 HTTPS 없이 시험할 수 있습니다. Tailscale 앱을 쓰면 외부망에서도 가능합니다. 다만 debug 앱은 Tailscale 주소를 HTTP 로 쓸 수 없어 네트워크 설정 추가가 필요합니다.

### 추가하면 좋은 새로운 기능

완전히 새로운 기능 아이디어는 별도로 논의하기로 했습니다. 이 문서에는 정하지 않습니다.

### 지금은 하지 않아도 되는 작업

HTTPS, 공개 도메인, 상시 운영 서버, 배포용 서명 키, 실제 문자, 홈캠·CCTV 실제 연결, 대규모 대응, 로그 회전, 계정 잠금 악용 방지 (H-3), 데이터 내보내기, 옛 안드로이드 앱과 옛 PC 규칙 정리.

옛 경로 삭제는 호출 기록을 본 뒤 원하면 합니다. Tailscale 안에서만 쓰는 동안에는 급하지 않습니다.
