# 지킴이 · 낙상 감지 서비스 (웹앱)

가족이 함께 쓰는 낙상 감지·알림 서비스의 모바일 웹앱 화면입니다.
카메라 감지 · 서버 · 119 연동은 이후 연결할 예정이며, 현재는 임시 데이터와 상태 값으로 모든 화면이 동작합니다.

## 현재 구현된 기능

- **온보딩** O-01~O-09: 가입 → 그룹 만들기/참여(QR·초대 코드, 24시간 만료, 매번 새 코드) → 감지 대상 질문 → 개인정보 → 주소(그룹 집 선택/검색) → 현관 비밀번호 → 기기 연결
- **탭 4개**: 홈 / 예방 / 가족 / 설정
  - 홈: 진행 중 사고 배너(마감 빠른 순), 집 단위 감지 현황(정상·주의·감지 중단, 이상 시 자동 펼침·문제 기기 맨 위), 내 폰 카메라 카드 / "알림만 받는 중" 카드, 설정 미완료 배너, 최근 알림
  - 가족: 집별 구성원 + "알림만 받는 분", 초대하기, 집 관리, 그룹 나가기
  - 설정: 내 프로필, 알림 설정, 회원 탈퇴
- **하위 화면** S-01~S-12 (기기 상세 시트, 낙상 이력 목록/상세, 구성원 상세, 집 상세, 초대, 비밀번호 변경, 그룹 나가기·회원 탈퇴 확인, 프로필 수정, 알림 설정, 감지 켜기 흐름)
- **긴급 이벤트** E-01~E-07: 어떤 화면 위에서도 전체 화면으로 표시. 낙상자 / 가족 / 대상자 선택 / 119 신고 확인 / 확인 중 / 신고 완료·종료
- **권한 규칙**: 개인정보는 본인만 수정, 주소·비밀번호·기기는 그 집에 연결된 사람만 수정, 비밀번호 값은 어디에도 표시하지 않고 "등록됨/미등록"만 표시
- **타이머**: 기준 시각(감지 시각, 자동 신고 예정 시각)을 상태로 저장하고 `예정 시각 − 현재 시각`으로 계산. 모든 화면이 같은 마감 시각 공유. 도움 요청을 반복해도 180초 마감은 처음 요청 기준 유지

## 실제 모드와 테스트 모드 (서버 연결 A단계에서 추가)

| | 실제 모드 (기본) | 테스트 모드 |
|---|---|---|
| 여는 주소 | `/app/next/` | `/app/next/index.html?mode=test`, `dev.html` 과 그 미리보기 창 |
| 데이터 | 서버 `/api/v2` 만 (`js/api-live.js`). 브라우저 저장소에 저장하지 않음 | 이 문서 아래의 예시 데이터 (`js/api.js`, 브라우저 `fd.state.v2`) |
| 사고 상태 변화 | 서버만 바꿈 (`advance()`·시간 배속 꺼짐, 응답 대기 60초·보호자 대기 180/90초는 서버 설정) | 지금처럼 가짜 타이머 |
| 서버 호출 | 함 | 하지 않음 (실제 기록·알림과 무관) |
| 표시 | 없음 | 위쪽 노란 띠 "테스트 모드 · 예시 데이터" |

- 모드는 `js/mode.js` 가 정합니다 (`FD.MODE`). 실제 모드에서 아직 서버 API 로 바꾸지 않은 동작은
  "이 기능은 아직 서버와 연결 중이에요" 안내만 하고 아무것도 바꾸지 않습니다 (`store.js` 의 `SERVER_ACTIONS`).
- 서버 연결 순서(B단계부터): 계정·로그인·그룹 → 가족·집 → 사고 대응·이력 → 가족 대응 → 기기·감지 상태 → 알림 → 나머지.
- **B단계에서 서버와 연결된 동작**: 가입(휴대전화+비밀번호), 로그인(`#/ob/login`), 로그아웃(설정), 그룹 만들기,
  초대 코드 발급·새로 만들기(24시간 뒤 만료), 코드로 참여, 그룹 나가기, 처음 설정 완료.
  - 서버 코드: `server/accounts.py`, DB 표: `server/db.py` 2번 변경(groups·users·invites·sessions·auth_failures).
  - 비밀번호는 scrypt 해시만 저장, 로그인 쿠키 `fd_session` 은 HttpOnly·SameSite=Lax(HTTPS 에서는 Secure), DB 에는 쿠키의 해시만.
  - 실제 모드는 10초마다(그리고 화면으로 돌아올 때) 서버 상태를 다시 읽어 다른 가족의 변화를 반영합니다.
  - 비밀번호 재설정은 문자 인증 단계에서 만들 예정이라 지금은 "준비 중" 안내만 나옵니다.
- **C단계에서 서버와 연결된 동작**: 내 이름·건강 정보(생년월일·지병·복용약) 수정, 알림 받기 설정 저장,
  처음 설정 완료(건강 정보 + 집을 서버가 한 트랜잭션으로 저장), 같은 집 연결·해제, 집 주소 수정, 회원 탈퇴(비밀번호 재확인).
  - 서버 코드: `server/people.py`(+ `accounts.py` 의 그룹 나가기·탈퇴), DB 표: `server/db.py` 3번 변경(users 열 추가, homes, home_members).
  - 권한은 서버가 확인: 내 정보는 본인만, 집은 내 그룹 안에서만 찾고(다른 그룹 집 id → 404) 연결된 사람만 주소 수정.
  - 주소: 도로명주소 검색 (서버 `GET /api/v2/address/search`, `server/address_search.py`). 승인키는 `server/.env` 의 `JUSO_API_KEY` 에만 두고
    브라우저로 보내지 않습니다. 로그인한 사람만, 1분에 30회까지. 검색이 안 되면 화면의 "직접 입력하기"로 입력할 수 있고,
    `api-live.js` 의 `addressSearch` 를 `false` 로 바꾸면 직접 입력만 씁니다. 테스트 모드는 예시 주소록 그대로.
  - 아직 "준비 중": 기기 연결(F단계), 내 폰 카메라, 휴대전화 번호 변경(문자 인증 단계), 집 변경 알림(G단계).
- **현관 비밀번호 (H단계)**: 처음 설정 3/4 단계와 가족 → 집 상세에서 등록·변경·삭제 (`server/door_codes.py`, DB 4번 변경).
  - 서버가 AES-256-GCM 으로 암호화해 `home_door_codes` 표에 저장. 키는 `server/.env` 의 `DOOR_CODE_KEY` (DB 와 분리, Git 제외).
    키가 없거나 틀리면 등록 요청은 503 이고 **평문으로 저장하지 않음**. 키 만들기: `server\venv\Scripts\python.exe door_codes.py genkey`
  - 규칙: 숫자, `*`, `#` 만 3~20자. 그 집에 연결된 가족만, 내 그룹의 집만 (다른 그룹 집은 404).
  - 화면·상태에는 **등록 여부만** (`centralPw`/`doorPw`). 값을 돌려주는 API 는 없음. 작업 기록(`home_events`)에도 값은 없음.
  - **키를 잃어버리면 저장된 현관 비밀번호는 풀 수 없음** (다시 등록해야 함). `fall.db` 를 백업할 때 키도 **따로, 안전하게** 보관하고,
    키와 DB 를 같은 곳(같은 압축 파일·같은 클라우드 폴더)에 두지 말 것. 복구할 때는 같은 키를 `.env` 에 넣어야 풀림.
  - 119 실제 전달은 없음 (확인 화면도 "등록됨"만 표시). 서버 내부용 `door_codes.reveal()` 은 D/E 단계 모의 신고 연결 때 설계.
- **현관 출입 방식 (DB 5번 변경 `home_entrances`)**: 현관마다 따로 — 중앙 현관 `code`/`key`/`absent`(중앙현관 없음),
  집 현관 `code`/`key`/`unlocked`(잠금장치 없음), 줄이 없으면 **미설정**. 상태에는 `centralAccess`/`doorAccess` 로 전달.
  - 비밀번호는 방식이 `code` 일 때만 등록 가능 (아니면 409, DB 트리거도 막음). 다른 방식으로 바꾸면 **그 현관의 비밀번호만** 삭제
    (화면에서 확인을 받음). 비밀번호 방식에서 입력 없이 저장하면 등록된 비밀번호는 그대로.
  - API: `PUT /api/v2/homes/{id}/entrances/{central|door}` `{method, code?}`, 처음 설정은 `entrances` 로 같은 트랜잭션.
  - 할 일·'입력 필요'는 미설정이거나 비밀번호 방식인데 미등록일 때만. 5번 변경 때 이미 등록된 비밀번호는 `code` 방식으로 보존.
  - 처음 설정(`#/ob/…`)과 감지 켜기(`#/enable/…`)는 같은 화면 처리기를 쓰므로, 처리기는 지금 화면 주소로 흐름을 정합니다 (`onboarding.js` 의 `curFlow`).
  - 그룹을 나가면 젠스파크 설계대로 감지 대상 표시·건강 정보·집 연결도 지워지고, 마지막 구성원이면 그룹과 집이 삭제됩니다 (탈퇴도 같음).

js/store.js         ★ 상태 · 선택자(Sel) · 동작(Act) · 사고 상태 전이(advance = 서버 대행 자리)

js/onboarding.js    O-01~O-09, S-12

js/family.js        가족, 구성원, 집, 초대, 주소·비밀번호·기기 추가 시트
js/settings.js      설정, 프로필, 알림 설정, 탈퇴

### 예방 탭 교체 방법
`js/prevent.js` 파일만 교체하면 됩니다. 계약은 `window.FD_PREVENT.render(container)` (선택: `destroy()`) 하나뿐이며, 다른 코드와 의존성이 없습니다. 현재는 탭 제목만 있는 최소 화면입니다.

### 실제 서버 연결 시
- `js/api.js` 의 `loadSnapshot / readSnapshot / writeSnapshot / searchAddress` 를 서버 호출로 교체
- 사고 이벤트(`incident` 객체: `detected → no_response/help → checking → reported/closed`)는 서버 데이터로 주입. `store.js` 의 `advance()`(60초 무응답 전이, 자동 119 신고)는 서버가 맡도록 제거

## 데이터 모델 (`FD.Store.state`)

- `groups` / `people`(이름·휴대전화·감지 대상자 여부·생년월일·지병·복용약·homeIds·phoneCamera·prefs) / `homes`(주소·centralPw·doorPw: 불리언만 보관) / `devices`(type·location·status: ok|disconnected|off)
- `incidents`: `detectedAt`, `status`, `familyNotifiedAt`, `autoReportAt`, `helpTimes[]`, `checkedBy/At`, `reportedBy/At`, `closedAt`, `log[]`
- `history`: 과거 낙상 이력, `notifs`: 가족 알림 기록, `clock`: 배속 가능한 가상 시계
- 저장소: 브라우저 `localStorage` (같은 브라우저의 여러 탭이 같은 사고 상태를 공유)
